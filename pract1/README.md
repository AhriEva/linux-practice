# Вариант 18: эмулятор UNIX-подобной оболочки

Практическая работа № 1 по конфигурационному управлению, ИКБО-13-25.
Реализованы все пять этапов варианта 18 (страницы 59–61 задания).
Язык — **C++17**, графический интерфейс — **Qt 6 Widgets**.

Приложение загружает виртуальную файловую систему из XML, показывает `motd`,
исполняет стартовый скрипт и принимает команды в графическом терминале.
Каталоги, содержимое файлов и права хранятся в памяти. Оболочка не запускает
команды реальной ОС и не записывает изменения VFS в исходный XML.

## Сборка и запуск

Нужны компилятор C++17, CMake 3.16+ и Qt 6.4+ с модулями Core, Widgets, Test.
Отдельные библиотеки для XML или base64 не нужны: используются средства Qt.

На macOS с Homebrew:

```sh
brew install cmake qtbase
./run.sh --vfs examples/full.xml --startup examples/startup/demo.txt
```

Универсальная сборка из каталога проекта:

```sh
cmake -S . -B build -DCMAKE_PREFIX_PATH="/путь/к/Qt/6.x/комплекту"
cmake --build build --config Release --parallel
```

Если Qt уже найден CMake, параметр `CMAKE_PREFIX_PATH` можно опустить.
На macOS/Linux исполняемый файл — `build/emulator`.
При сборке Visual Studio — `build/Release/emulator.exe`; можно использовать
`run.bat` из среды разработчика Visual Studio с настроенным Qt.

```sh
./build/emulator --vfs examples/full.xml --startup examples/startup/demo.txt
./build/emulator --vfs examples/minimal.xml
```

`run.sh` и демонстрационные скрипты переходят в каталог проекта.
При прямом запуске бинарника относительные пути считаются от рабочего каталога.
Скрипты поддерживают переменную `BUILD_DIR` для другого каталога сборки.

## Настройки

| Параметр | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `--vfs PATH` | `examples/full.xml` | Физический путь XML-образа VFS |
| `--startup PATH` | пусто | Физический путь стартового скрипта UTF-8 |
| `--headless` | выключен | Дополнительный режим проверки сценария без окна |
| `--help` | — | Справка по параметрам |

При запуске параметры выводятся в журнале в формате `ключ=значение`.
Команда `conf-dump` повторяет этот вывод. Заголовок окна имеет вид
`Эмулятор - [username@hostname]` и использует реальные данные ОС.
Приглашение показывает текущий **виртуальный** путь: `/home/student$`.

## Команды

| Команда | Поведение и поддержанные режимы |
| --- | --- |
| `ls [-al] [путь]` | Список по имени; `-a` включает скрытые, `.` и `..`; `-l` показывает тип, восьмеричные права и размер в байтах |
| `cd [путь]` | Смена каталога; без аргумента — `/` |
| `tree [-ad] [-L N] [путь]` | Дерево; `-a` включает скрытые, `-d` оставляет каталоги, `-L N` ограничивает глубину положительным числом |
| `whoami` | Имя реального пользователя ОС |
| `uniq [-c] [-d\|-u] файл` | Удаление соседних повторов; `-c` выводит число, `-d` только повторы, `-u` только одиночные группы |
| `mkdir [-p] [-m MODE] путь...` | Создание каталогов; `-p` создаёт родителей, `-m` задаёт восьмеричные права последнего компонента |
| `chmod [-R] MODE путь...` | Изменение прав; `-R` рекурсивно обходит дерево |
| `conf-dump` | Текущие значения параметров запуска |
| `exit` | Завершение сеанса и закрытие окна |

`ls`, `tree`, `uniq`, `mkdir` поддерживают `--` перед путями, начинающимися с `-`.
У `chmod` `--` допускается перед MODE; после MODE все аргументы считаются путями.
Короткие флаги `ls -al`, `tree -ad`, `uniq -cd` можно объединять.
`uniq -d` и `uniq -u` взаимоисключающие; `-c` сочетается с каждым из них.
Сравнение строк точное, без сортировки: `A A B A` превращается в `A B A`.
Пустой файл даёт пустой результат; завершающий перевод строки сохраняется.

Примеры масок `chmod`: `644`, `0755`, `u+x`, `go-rwx`, `u=rw,g=r,o=`, `a=rx`.
Поддержаны только биты `rwx` и группы `u/g/o/a`; без группы используется `a`.
Символьные маски обрабатываются слева направо. Специальных битов, копирования
прав через `g=u`, флага `X` и системной `umask` нет.

Все узлы считаются принадлежащими одному виртуальному пользователю.
Для доступа используются биты владельца: `r` — чтение файла/каталога,
`w+x` — создание в каталоге, `x` — проход по каталогу.
`chmod` доступен владельцу даже при нулевых правах самого узла;
для `-R` требуется чтение и проход по обходимым каталогам.
Права `g/o` сохраняются и отображаются, но отдельных пользователей VFS нет.

Пути поддерживают `/`, `.`, `..`, повторные `/`; переход выше корня остаётся в `/`.
Нормализация пути лексическая: компоненты `.` и `..` сворачиваются до поиска узла.
Есть одинарные/двойные кавычки, пустые аргументы `""`, экранирование обратной
косой чертой вне одинарных кавычек. Пустой путь является ошибкой.

Реализован перечисленный набор режимов, а не полная POSIX-оболочка:
нет конвейеров, перенаправлений, раскрытия переменных, масок `*`, ссылок и stdin
для `uniq`. Аргумент `uniq` всегда указывает на текстовый файл UTF-8 внутри VFS.

## XML-файловая система

```xml
<?xml version="1.0" encoding="UTF-8"?>
<vfs mode="755">
  <file name="motd">Добро пожаловать!</file>
  <dir name="docs" mode="755">
    <file name="a b.txt" mode="644">Первая строка
Первая строка
Вторая строка
</file>
  </dir>
  <file name="data.bin" encoding="base64">AAECA//+</file>
</vfs>
```

Корень — `<vfs>`, каталог — `<dir name="...">`, файл — `<file name="...">`.
Имена не должны содержать `/`, быть пустыми, `.` или `..`; в одном каталоге
повторы имён запрещены. Вложенность задаётся вложенностью XML-элементов.
Для каталогов по умолчанию `mode="755"`, для файлов — `mode="644"`.
У корня можно задать `mode`. Поддержана вложенность до 128 уровней.

Файлы без `encoding` или с `encoding="text"` содержат текст; пробелы и переводы
строк внутри `<file>` сохраняются. Двоичные файлы используют `encoding="base64"`.
XML-символы в тексте экранируются стандартно (`&amp;`, `&lt;`). DTD запрещены.
Некорректный XML, base64, права или отсутствующий файл вызывают ошибку загрузки.
Частично загруженное дерево не заменяет старую VFS.

Если есть корневой `/motd`, его текст выводится **до** стартового скрипта.
Нечитаемый, двоичный или являющийся каталогом `motd` считается ошибкой запуска.

Примеры образов:

- `examples/minimal.xml`: пустой корень, без `motd`.
- `examples/files.xml`: несколько файлов, скрытый файл, base64 и `motd`.
- `examples/full.xml`: файлы и три уровня каталогов, имена с пробелами.

## Стартовые сценарии и ошибки

Скрипт — текстовый файл UTF-8, одна команда на строку. Комментарии используют
синтаксис C++ `//` в начале слова вне кавычек. Например:

```cpp
// Демонстрация кавычек и комментария
cd "/home/student/folder with spaces"
ls "a b.txt" // комментарий после команды
```

В журнале отображаются ввод и вывод. После ошибки команды выполнение
продолжается; журнал содержит имя скрипта и номер строки. `exit` останавливает
оставшиеся строки и завершает сеанс. Неизвестные команды, опции, лишние/недостающие
аргументы, незакрытые кавычки, отсутствующие пути, неверные типы узлов и запреты
доступа сопровождаются сообщением `Ошибка: ...`. Сбой открытия скрипта также
показывается в журнале. В GUI после ошибки можно продолжать работу.

Коды завершения `--headless`: `0` — успех, `1` — ошибка стартового скрипта
или его команд, `2` — ошибка VFS/аргументов запуска. Ошибка загрузки VFS в GUI
показывается отдельным диалогом, приложение завершается с кодом `2`.

## Проверка и демонстрация

```sh
cmake -S . -B build
cmake --build build --config Release --parallel
ctest --test-dir build -C Release --output-on-failure
./scripts/demo.sh
./scripts/check.sh
```

Пять наборов тестов проверяют парсер/основные команды, XML/base64, изменения
прав и каталогов, стартовые скрипты, графический ввод и выход. Тест GUI запускается
через плагин Qt `offscreen`; команды вводятся с помощью Qt Test.
Отдельный тест сравнивает SHA-256 исходного XML до и после изменений VFS.

- `scripts/config-demo.sh`: два GUI-запуска с обоими параметрами.
- `scripts/vfs-demo.sh`: GUI-запуски для трёх образов VFS.
- `scripts/demo.sh`: успешная демонстрация, окно остаётся открытым.
- `scripts/check.sh`: сборка, тесты и сценарии всех этапов без окна.
- `examples/startup/stage2.txt` … `stage5.txt`: режимы команд и намеренные ошибки.
- `examples/startup/exit.txt`: успешный сценарий даже для пустого образа.

В проверочных сценариях этапов ошибки **преднамеренны**, поэтому ожидается код `1`.
Подробный план интерактивной защиты находится в `docs/DEFENSE.md`.

## Устройство проекта и функции

| Файл/функции | Назначение |
| --- | --- |
| `src/main.cpp`: `main` | Разбор запуска, загрузка VFS/motd, выбор GUI или проверки без окна |
| `Config::dump`, `readConfig` | Хранение, вывод и разбор параметров |
| `parseLine` | Разбор строки с кавычками, экранированием, комментариями |
| `Shell::execute`, `dispatch` | Выполнение команд и преобразование исключений в результат |
| `Shell::loadVfs`, `motd`, `cwd`, `closed` | Загрузка образа и доступ к состоянию сеанса |
| `Vfs::load`, `resolve`, `readText`, `motd` | Чтение XML, поиск узлов, чтение текста и приветствия |
| `absolutePath`, `numericMode`, `requireAccess` | Нормализация путей, разбор прав, проверка доступа |
| `listCommand`, `changeDirectory`, `treeCommand`, `uniqueCommand` | Логика основных команд |
| `mkdirCommand`, `chmodCommand` | Операции изменения состояния VFS в памяти |
| `parseOptions` | Общий разбор коротких флагов, `--`, глубины дерева |
| `runStartup` | Построчное исполнение сценария с журналом и диагностикой |
| `currentUser` | Получение имени пользователя реальной ОС |
| `Terminal::write`, `runLine` | Вывод журнала и выполнение строки из GUI |
| `tests/` | Независимые проверки ядра, сценариев и GUI |

Конструкторы создают начальное состояние: `Vfs` — пустой корень, `Shell` —
сеанс в `/`, `Terminal` — виджеты окна. `ShellError` хранит сообщение ошибки.
Внутренние вспомогательные функции находятся в анонимных пространствах имён:
разбор/проверка XML, форматирование списка и обход дерева, разбор параметров
`mkdir`, создание компонентов пути, преобразование масок `chmod` и сбор узлов
для рекурсивного изменения. Их назначение отражено именами и небольшими
отдельными функциями; интерфейсы описаны Doxygen-комментариями в заголовках.

## История этапов

В каталоге `.git` сохранён локальный репозиторий с пятью отдельными коммитами
Conventional Commits и метками `stage-1` … `stage-5`:

1. `feat(repl)` — GUI, парсер, заглушки `ls`/`cd`, `exit`.
2. `feat(config)` — параметры запуска, скрипты, `conf-dump`.
3. `feat(vfs)` — XML/base64 в памяти и `motd`.
4. `feat(commands)` — `ls`, `cd`, `tree`, `whoami`, `uniq`.
5. `feat(mutation)` — `chmod`, `mkdir`, итоговые тесты и документация.

Посмотреть: `git log --oneline --decorate`. Для просмотра раннего этапа можно
создать отдельную рабочую копию: `git worktree add ../stage1 stage-1`.
История сохранена локально; публикацию на публичном git-сервисе нужно выполнить
со своего аккаунта. Готовый репозиторий не содержит бинарников и артефактов сборки.
