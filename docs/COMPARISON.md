# Сравнение с Cargo

Cargo используется только как независимый эталон. Приложение dependencies
не запускает Cargo и самостоятельно читает sparse index, разбирает версии,
активирует features и обходит зависимости.

## Порядок загрузки (этап 4)

Проверено на macOS Apple Silicon 16 октября 2026 года, Cargo 1.99.1.
Для getrandom@0.2.16 приложение при глубине 20 получило:

```text
cfg-if@1.0.5
libc@0.2.190
wasi@0.11.1+wasi-snapshot-preview1
getrandom@0.2.16
```

Независимый запуск `cargo build --jobs 1 -vv` на проекте
examples/cargo/getrandom показал строки Compiling в порядке:

```text
libc v0.2.190
cfg-if v1.0.5
getrandom v0.2.16
comparison-getrandom v0.1.0
```

Оба порядка ставят зависимости перед getrandom. Перестановка независимых
libc/cfg-if допустима: топологическая сортировка не уникальна. Приложение выбирает
готовый узел по алфавиту, Cargo использует собственный планировщик. wasi присутствует
в графе приложения, потому что рассматриваются зависимости для всех target,
а сборка Cargo выполнялась только для текущей macOS. comparison-getrandom —
вспомогательный проект сравнения и не является зависимостью getrandom.

При цикле приложение отказывается выдавать полный порядок. Усечённый глубиной
или фильтром граф даёт порядок только исследованного подграфа.

## Графы и визуализация (этап 5)

Для сравнения взяты три опубликованных пакета. У приложения задана глубина 20,
фильтр выключен, зависимости берутся для всех target. Эталон запущен так:

```sh
cargo tree --manifest-path examples/cargo/getrandom/Cargo.toml \
    -p getrandom --target all -e normal,build --charset ascii
```

Для itoa и rand_chacha использованы соответствующие manifest-path и имя пакета.
Дополнительно `cargo tree --prefix depth --format '{p}' --no-dedupe` позволил
независимо восстановить пары родитель/зависимость. Эти пары и множество узлов
сравнены с рёбрами и узлами сгенерированного PlantUML.

| Корень | Узлы | Рёбра | Сравнение версий и связей |
| --- | --- | --- | --- |
| itoa@1.0.15 | 1 | 0 | Полное совпадение |
| getrandom@0.2.16 | 4 | 3 | Полное совпадение |
| rand_chacha@0.3.1 | 9 | 12 | Полное совпадение |

У getrandom получены cfg-if@1.0.5, libc@0.2.190,
wasi@0.11.1+wasi-snapshot-preview1. У rand_chacha есть транзитивная цепочка
через ppv-lite86, zerocopy, zerocopy-derive и proc-macro-зависимости.
У itoa нет активных обычных/build зависимостей: один узел — ожидаемый результат.

Снимки находятся в `examples/real`: `.puml` — PlantUML, `.txt` — вывод приложения,
`-cargo.txt` — независимый вывод Cargo. Новые версии транзитивных пакетов могут
изменить результат будущего запуска: корневая версия закреплена, Cargo.lock
приложением не используется.

Семантических расхождений для этих трёх графов не обнаружено. Различается
представление: наше дерево использует имя@версия, Cargo — имя vверсия и отдельную
пометку proc-macro. Выбор ветки первого раскрытия общей зависимости также может
различаться: приложение сортирует соседей и использует единый набор посещённых
узлов. Все связи при этом полностью присутствуют в PlantUML.

Результат не означает полного совпадения со всеми проектами Cargo: сложный
глобальный подбор версий, MSRV, lockfile, разделение features host/target и другие
ограничения перечислены в README.md. Без `--target all` Cargo скрывает зависимости
других платформ, поэтому такое сравнение заведомо дало бы отличия.

Правила интерпретации эталона описаны в
[официальной документации cargo tree](https://doc.rust-lang.org/cargo/commands/cargo-tree.html).
